# TRON 扫描器地址同步实施计划

## 1. 目标

将 `wallet-chain-server` 中需要监控的 TRON 地址同步到扫描器本地数据库和内存，并在地址已经持久化且对扫块线程可见后确认监控水位。

## 2. 系统边界

### wallet-chain-server

- 管理地址及其状态。
- 提供币种配置和地址增量同步接口。
- 接收扫描器应用水位 ACK。
- 将已确认监控的地址从 `PENDING_MONITOR` 更新为 `ACTIVE`。

### wallet-tron-scanner

- 调用链服务同步币种和地址。
- 将地址幂等保存到本地 `tron_monitor_address`。
- 从本地数据库构建内存地址索引。
- 只有本地地址全部加载到内存后，才把当前网络最大的 `source_address_id` 作为应用水位。
- 将应用水位 ACK 给链服务。
- 不读取链服务数据库，不接收 `keyRef` 和用户绑定信息。

## 3. 开发顺序

1. 在 `wallet-chain-server/chain-client` 定义币种查询、地址增量查询和 ACK 契约。
2. 在 `wallet-chain-server` 实现三个内部接口及网络校验。
3. 在扫描器建立 `tron_monitor_address` 和 `tron_scan_checkpoint`。
4. 在扫描器实现 `ChainServerClient`。
5. 实现本地地址仓库和线程安全内存地址索引。
6. 实现分页同步流程，只有本地写入且本页地址全部进入内存后才更新应用水位并发送 ACK。
7. 增加 `AddressSyncJob`，由 XXL-JOB 串行触发。
8. 测试重复同步、分页中断、ACK 失败、服务重启和百万地址内存占用。

地址同步不建立单独检查点。启动时从本地表重建内存索引，再查询当前网络的最大 `source_address_id` 作为安全应用水位。若数据库写入成功但内存更新失败，scanner 必须进入未就绪状态并从本地表重建索引，期间不得 ACK 或执行扫块。

## 4. 当前阶段不实现

- TRON Head 扫块和充值固化确认。
- TRX、TRC20 交易解析。
- 充值交易上报。
- 节点健康检查与自动切换。
- 地址与用户绑定关系。

完整边界、表结构和故障恢复方案见 [TRON 扫描器详细设计](TRON扫描器详细设计.md)。

# 阶段6：TRON固化充值扫描闭环

本文描述当前 `wallet-tron-scanner` 的实际流程。Scanner 只扫描 SolidityNode 已固化高度以内的区块，向 Kafka 发送最终充值事件；不再扫描未固化 Head 区块，也不再保存区块历史或自动回退。

## 1. 核心流程

```text
加载地址和币种内存索引
→ 读取本地检查点 H / Hash-H
→ 从节点重新读取 H，复核检查点 Hash
→ 查询 SolidityNode 最新固化高度 S
→ 计算本轮终点 min(S, H + max-blocks-per-run)
→ 从 H + 1 开始顺序读取完整区块和回执
→ 校验高度及 parentBlockId
→ 解析进入平台地址的 TRX / TRC20 充值
→ 有充值时发送 DepositConfirmedEvent 并等待 Kafka ACK
→ 更新检查点
→ 继续下一块
```

只有完整完成“读取、连续性校验、解析、Kafka ACK、检查点更新”的区块才算扫描成功。

## 2. 为什么只扫描固化区块

SolidityNode 返回的是 TRON 已固化链视图。Scanner 以它的最新高度作为上界，因此发出的 `DepositConfirmedEvent` 可以直接表达最终充值事实。

这样删除了旧流程中的三部分：

- 未固化充值发现事件和 `CONFIRMING` 中间状态。
- Chain Server 再次查询 SolidityNode 的重复确认任务。
- Scanner 保存最近区块摘要、查找共同祖先和自动回退检查点。

FullNode 仍负责读取完整区块和交易回执，因为 SolidityNode 只负责提供固化边界。读取的数据必须满足本地检查点连续性。

## 3. 扫描边界

假设：

- 本地检查点为 `1000 / H1000`。
- SolidityNode 最新固化高度为 `1250`。
- `max-blocks-per-run = 100`。

本轮只扫描 `1001～1100`。下一轮从 `1101` 继续，直到追上 `1250`。

Scanner 不读取 `1251` 之后的未固化区块，也不使用 FullNode Head 高度决定充值扫描范围。

## 4. 单区块处理与提交顺序

### 4.1 有充值的区块

```text
读取区块和回执
→ 校验区块连续性
→ 解析充值
→ 分批发送Kafka并等待全部ACK
→ 更新检查点
```

单条事件最多携带 300 笔充值。同一区块拆成多条消息时，只要其中一条发送失败，检查点就不推进；下轮从该区块重新发送全部分组。Chain Server 使用充值唯一键保证幂等。

### 4.2 空区块

空区块不发送 Kafka，连续性校验通过后直接更新检查点。

### 4.3 为什么允许重复发送

数据库更新失败可能发生在 Kafka ACK 成功之后。此时 Scanner 无法证明消息是否已经被消费，因此保持旧检查点并在下一轮重发。重复发送比漏单安全，最终由 Chain Server 幂等接收。

## 5. 固化链连续性

每轮和每块各做一次校验：

1. **检查点复核**：重新读取本地检查点高度，节点 Hash 必须等于本地 Hash。
2. **新区块校验**：新区块高度必须是 `H + 1`，父 Hash 必须等于检查点 Hash。

固化证据按协议不应改变。任何不一致都可能表示节点异常、网络配置错误、数据库被错误修改或极端链故障。Scanner 会：

```text
记录 ERROR 916003 和关键证据
→ 停止本轮
→ 不发送当前异常区块
→ 不修改检查点
→ 等待人工核对节点与数据库
```

Scanner 不自动寻找共同祖先，也不自动回退已经确认的充值。

## 6. 故障恢复矩阵

| 故障位置 | 检查点结果 | 下一轮行为 |
|---|---|---|
| 查询固化高度失败 | 不变 | 重新查询固化边界 |
| 读取区块或回执失败 | 不变 | 从同一高度重读，节点池可切备用节点 |
| 区块高度或父 Hash 不连续 | 不变 | 持续阻断并输出 ERROR，等待人工处理 |
| 充值解析失败 | 不变 | 从同一高度重新解析 |
| Kafka ACK 失败或超时 | 不变 | 重发同一区块全部消息 |
| Kafka 已 ACK、检查点更新失败 | 不变 | 重发消息，由 Chain Server 幂等去重 |
| 前面区块成功、后续区块失败 | 保留最后成功高度 | 从失败区块继续 |
| 服务重启 | 从数据库恢复 | 复核检查点后继续顺序扫描 |

## 7. 代码职责

| 类 | 职责 |
|---|---|
| `HeadBlockScanJob` | 定时触发一轮扫描 |
| `HeadBlockScanService` | 组织检查点复核、扫描范围和逐块处理 |
| `HeadBlockContinuityService` | 校验检查点 Hash、新区块高度和父 Hash |
| `TronNodeManager` | 查询固化高度，读取完整区块并完成主备节点切换 |
| `DepositDiscoveryService` | 解析与平台地址有关的 TRX / TRC20 充值 |
| `DepositConfirmedPublisher` | 分批发送最终充值事件并等待 Kafka ACK |
| `HeadScanProgressService` | 初始化和推进唯一检查点 |

入口从 `HeadBlockScanService.scanBlocks()` 开始看。节点请求和 Kafka 等待均不持有数据库事务；检查点每块只执行一次短更新。
